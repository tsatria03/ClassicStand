Bugs that affect what the player sees or loses. Items 1–4 found during the full-repo evaluation; items 5–7 confirmed from real **player feedback** (both **2026-08-20, game v3.3**). Verify each still exists before fixing ([[feedback_verify_code_while_fixing]]); re-locate by symbol, not line number. Design/balance *suggestions* (not bugs) from the same feedback live in [[project_design_feedback]]; internal-quality problems in [[project_known_code_issues]].

**1. Save-data loss — several bits of game state are never persisted.** `savefuncks.nvgt` `writedata()`/`readdata()` are a hand-maintained key list with **no version field**. Confirmed gaps: `poster_tiles` (the placed-poster dedup list) is NOT saved though `placed_posters` is, so on reload the "one poster per tile" guard in [[project_data_driven_config]] inventory logic is defeated; the per-cup recipe arrays (`cup_lemons`/`cup_sugars`/`cup_waters`/`cup_ices`/`cup_salts`) are NOT saved, so every filled cup silently collapses to the `last_*_per_cup` values on reload; napkins/`used_napkin` and `floor_spilled` are NOT persisted, so an active spill/cleanup quest vanishes on reload. This reads to the player like the game "cheating" — highest-priority player-facing issue.

**2. Load/New-game menu fall-through. — ✓ FIXED in 3.4 (verified 2026-08-20).** `menu.nvgt` `loadgamemenu` and `newgamemenu`: the Escape (`mres==-1`) and "back" branches called `gamemenu()` **without `return`**, falling through to `string_to_int(slotem.substr(2))` — for `"back"` that yielded slot `0`, landing in the "save slot doesn't exist" error. Fix: added `return;` after `gamemenu()` in all four branches; also made `newgamemenu`'s inner "start over?" yes/no dispatch return consistently on all three branches. Changelogged under 3.4.

**3. Dock viewer opens a missing file. — ✓ FIXED in 3.4 (verified 2026-08-20).** `extrafuncts.nvgt` `dockread` (~:446): the missing-file branch alerted and called `docksmenu()` but did NOT `return`, then fell through to `dockfile.open()` on a nonexistent file. Fix: added `return;` after `docksmenu()`; also corrected the alert wording `"Could not fined"` → `"Could not find"`. Changelogged under 3.4.

**4. Spill cleanup never removes the wet patch + platform accretion.** Two verified problems in the spill/clean path (`customer.nvgt:418`/`774` spawn the wet patch; `inventory.nvgt:124` "cleans" it): (a) The spill spawns a `spring` (wet) platform on the counter tile (`COUNTER_X,COUNTER_Y` = 14,25). Cleaning with a napkin only flips `floor_spilled=false` and spawns a `marble` platform at the UNRELATED tile (32,50) — it never removes or overrides the wet patch at 14,25. Since `gmt()` is last-match-wins and the spring patch was inserted after the map's base surface, the counter tile keeps playing the wet step sound after cleaning, for the rest of the session. (b) `spawn_platform` only ever `insert_last`s; `remove_platform` exists but is **never called anywhere**, so every spill and every clean permanently grows the `platforms` array (memory + slower `gmt()` scans), cleared only on leaving the map. My original wording "stacks a new tile over the old one" was wrong — the cleanup tile lands elsewhere entirely.

**5. Empty-cup count only ever rises (broken cup economy).** Pouring lemonade does `fullcups += pourcount` (`menu.nvgt:446`) but **never decrements `cups`** — making a filled cup doesn't consume an empty one. Serving then does `cups += cups_needed` (`customer.nvgt:437`/`481`, and the serve-all path) — it hands an empty cup *back* on every sale. Net: empty cups climb forever and never fall, regardless of how many were bought. A player reported this directly. The intended model (from feedback) is either lend→return (−1 on serve, +1 on return) or route sold cups into a "used"/discard category; pour should consume an empty cup.

**6. Spoiled ingredients are wiped before they can be discarded.** Overnight spoilage adds items via `give("melted ice"/"rotted lemon"/"evaporated water"/"clumped salt", …)` (`extrafuncts.nvgt:509–543`), but `sync_inv()` (`inventory.nvgt:5–23`) runs every frame: it `inv.delete_all()`s and rebuilds inventory from the numeric counters, preserving ONLY napkins and posters. Spoiled items aren't in that preserve list, so they vanish one frame after being added — the player never gets to discard them, defeating the changelog's "added to your inventory to discard" promise. Fix: either back spoiled items with real counters (like the six base ingredients) or add them to the `sync_inv` preserve set.

**7. "Serve all" ignores group size (groups mis-served and under-charged).** Individual serve handles groups correctly (`cups_needed = group_size`, charges per cup), but the **serve-all** path does `fullcups -= 1; earned = selling_price;` per waiting customer (`customer.nvgt:743–745`) — one cup and one cup's payment regardless of group size. This is the concrete mechanism behind the long-standing todo item "group customers being treated as one singular customer," and it matches the player's report that some groups share a single cup while individually-served groups correctly need several. Fix the serve-all path to use each customer's `group_size` for both cups consumed and amount charged.
